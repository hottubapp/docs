    Page layout rows

    Overview

    On Home (browse), POST /api/videos returns an items array that can mix two shapes:

    1. Leaf videos — normal grid cells in the main waterfall. Each object looks like a full video row and must include a top-level url (watch page / permalink), same as the rest of the videos API.
    2. Featured rows — server-driven blocks with their own header and a nested items array of videos. These render as horizontal rails or an inline 2×2 Tapes-style grid, not as single waterfall tiles.

    The iOS client tells them apart by shape: a featured row has type, items, and no top-level url. If type, items, and url are all present at the top level, the object is treated as a leaf video, not a featured row.

    JSON key names

    Keys can be snake_case or camelCase; the app uses flexible decoding. See JSON key names.

    Featured row object

    Featured rows mirror the app’s FeaturedSection model.

    Field Type Required Description
    id string Yes Stable id for the row (diffing / analytics).
    title string Yes Section header shown in the UI.
    type string Yes Layout bucket; see Layout type below.
    items video[] Yes Ordered clips for this row. Each entry uses the same video fields as leaf items (including nested url).
    system_symbol string No SF Symbol name for the section header (e.g. person, square.grid.2x2, film.stack.fill).

    Layout type

    The client maps JSON type into exactly two layout buckets:

    type value Layout bucket Home UI
    grid Grid Inline 2×2 Tapes grid — four portrait-style tiles in a block; users can open a full-screen Tapes flow seeded with all nested video ids (not only the four on screen).
    Anything else Rail Horizontal videos rail — sideways-scrolling strip of video cards (same rail pipeline as topic/creator-style rows).

    Horizontal rail variants (Tapes portrait chrome)

    For type other than grid, the app still chooses card chrome:

    • Standard rail — landscape-style cards when clips look like normal browse tiles.
    • Tapes-style portrait rail — taller “shorts” cards when any of the following is true:
    • type is tapes, or
    • system_symbol suggests a film-stack symbol (e.g. contains film.stack), or
    • several of the first clips look like portrait, short items (the app uses aspect_ratio / aspectRatio and duration heuristics when symbols are absent).

    Per-video system_image / systemImage on nested items can also contribute to Tapes-style detection.

    Rails that use Tapes-style layout open to the full-screen Tapes experience on tap, similar to the dedicated Tapes entry points in the app.

    Inline 2×2 grid behavior

    When the row is a grid:

    • The UI shows up to four tiles from the start of items (2×2). Additional ids in items are still loaded and used when the user opens the full Tapes-style feed from the block.
    • Nested videos should be portrait-first short clips for best results (same intent as the first-party Tapes catalog: strong thumbnails and consistent aspect ratio).
    • system_symbol on the row overrides the default grid header icon when non-empty.

    Muted rotating previews on those tiles follow the user’s in-app auto preview setting; that behavior is not controlled from the API.
